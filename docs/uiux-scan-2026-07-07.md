## Major

**M1 — Dead links all over listing detail pages (~19 per page).**
In "Similar Lists" cards the photo and the ♥ bookmark icon are `href="#"` — clicking
scrolls to top instead of opening the listing / bookmarking. Only the small title text
navigates. Files: `src/pages/listing/[slug].astro` (topLink + bookmarkList in similar
cards; same pattern in other card grids). Fix: point image link at the listing URL,
make the heart a real bookmark control (or remove it for guests).

**M2 — Missing `<h1>` on key templates.**
`/listings/`, `/listings-grid/`, every `/listing/*` detail page (title is an `<h4>`),
`/login/`, `/register/`, and all dashboards (h2 only). Listing detail is the big one —
hurts SEO and screen-reader navigation. Fix: promote the listing title to `<h1>`
(restyle to keep the design), add page h1s (sr-only is fine) elsewhere.

**M3 — Stale/incomplete sitemap + legacy menu link.**
`/listing/bouganville-bed-breakfast-apartment/` is live but absent from sitemap.xml —
the sitemap is a build-time artifact so newly published listings wait for the next
deploy. Consider an SSR sitemap endpoint. Also the nav still links
`/things-to-do/boat-trips/` which 301s to `/tours/boat-trips/` — link the final URL.

## Minor / accessibility polish

**A1 — Icon-only controls with no accessible name:** 8 per listing page (gallery
arrows, share, heart), 3 on blog detail. Add `aria-label`.

**A2 — Images missing alt text:** 8–16 per taxonomy page and the map page (card
images). Use the listing title as alt.

**A3 — Labels not associated with inputs:** profile page (17 fields), booking page
(7 fields) — labels are visible but lack `for=`/`id`, so screen readers announce
nothing. Add `for`/`id` pairs.

**A4 — Small tap targets on mobile (<30 px):** breadcrumb links, footer quick links,
carousel dots, Leaflet attribution. WCAG suggests ≥44 px; add padding.
